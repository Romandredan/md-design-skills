# Было / стало для доработки формы

Результат — документ, где по каждой затронутой странице формы рядом стоят «было» и «стало», и таблица изменений. Заказчик согласует доработку по картинкам, разработчик получает точный перечень правок.

Разметку «Стало» пиши по правилам и справочнику ловушек навыка **md-design-prototype** (`references/syntax.md`), снимай — его исполнителями. Этот навык добавляет к нему получение текущей формы и сравнение.

## 1. Выяснить доработку и выбрать источник «было»

Из запроса выясни: какая форма (объект и форма, например «Документ ЗаказНаПеремещение, форма документа»), что меняется (поля, кнопки, страницы, поведение), какие страницы затронуты.

Затем **предложи пользователю выбрать**, откуда взять текущую форму, и коротко назови цену каждого способа:

| Способ | Что получится | Что нужно от пользователя | Ограничения |
| ------ | ------------- | ------------------------- | ----------- |
| **Публикация базы** | Снимок настоящей формы со всем, что делает её модуль: программные элементы, условное оформление, данные | База (файловая или серверная), пользователь 1С, навигационная ссылка на форму или объект («Получить ссылку», Shift+F11); пароль — через переменную окружения, не в чате | База публикуется на время прогона только на `127.0.0.1`; в снимок попадают реальные данные открытого объекта; вход в режиме предприятия на базу с неприменённым обновлением запускает обновление — подходит база, где пользователь и так работает. **Исполнитель снимка реальной формы на 29.10.2026 не проверен на базе с конфигурацией — предупреди об этом** |
| **Разбор XML** | Схема формы, построенная «Накидкой» по `Form.xml`: та же структура страниц, групп, полей и кнопок | Путь к `Form.xml` в XML-выгрузке (конфигурация, расширение, обработка) | Не видно элементов, создаваемых программно, условного оформления, стандартных команд автозаполняемой панели; ширины и растягивание приблизительны; данные — условные примеры |
| **Скриншоты пользователя** | Снимки, которые пользователь сделал сам в своей базе | PNG каждой затронутой страницы формы | Агент воспроизводит форму разметкой по снимку вручную — «стало» по оформлению будет схематичнее «было» |

Если пользователь не выбрал, а `Form.xml` доступен — предложи разбор XML: он не требует доступа к базе и даёт одинаковую по оформлению пару «было — стало».

## 2. Получить «было»

**Разбор XML.** Запусти конвертер:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<каталог навыка>\scripts\form-xml-to-markup.ps1" `
  -FormXml "<…\Forms\<Форма>\Ext\Form.xml>" -Out "<каталог>\bylo.txt" [-ObjectXml "<XML объекта>"]
```

Конвертер пишет разметку и печатает JSON-отчёт: `pages`, `elements`, `hidden` (невидимые элементы), `unsupported` (элементы без аналога в «Накидке» — на схеме серой надписью или пропущены, как картинки), `approximated` (что показано приближённо), `notes`. XML объекта метаданных (`<Объект>.xml` рядом с каталогом объекта) он находит сам: из него берутся синонимы и типы реквизитов — без него поля подписаны именами реквизитов. Отчёт не выбрасывай: его пункты `unsupported`, `notes` и существенные `approximated` попадают в документ разделом «Что не показано на схеме».

Сними `bylo.txt` исполнителем (по умолчанию веб, вместе с «стало» одним вызовом — шаг 3). Большие типовые формы содержат десятки страниц и колонок: снимай только затронутые страницы (`-Pages`).

**Скриншоты пользователя.** Попроси PNG каждой затронутой страницы в обычном масштабе. Воспроизведи затронутые страницы разметкой `bylo.txt` по снимку (заголовки, порядок, группы) — она нужна как основа «стало», сама в документ не идёт: «было» в документе — снимки пользователя.

**Публикация базы.** До проверки исполнителя на базе с конфигурацией этот способ не выполняй молча: скажи пользователю, что исполнитель не проверен, и предложи разбор XML или скриншоты.

## 3. Написать «стало» и снять

- `stalo.txt` — копия `bylo.txt` с доработкой. Меняй только то, что относится к доработке: неизменные строки совпадают, и разница на снимках видна сразу.
- Новые элементы пиши по справочнику ловушек `md-design-prototype`.
- Сними обе разметки одним вызовом веб-исполнителя: `-Markup "bylo.txt;stalo.txt"` и при необходимости `-Pages`. Снимки — `bylo-NN.png`, `stalo-NN.png`.
- Посмотри каждый снимок (правила — шаг 4 навыка `md-design-prototype`); сравни пары: отличаться должна только доработка.

## 4. Отдать результат

Документ рядом со снимками:

1. Что дорабатывается (2–3 предложения) и источник «было» (база, разбор XML или скриншоты — с ограничениями способа одной фразой).
2. По каждой затронутой странице — «Было» и «Стало» снимками подряд.
3. Таблица изменений: `Где (страница, группа) | Было | Стало | Зачем`.
4. «Что не показано на схеме» — для разбора XML: пункты отчёта конвертера, которые касаются затронутых страниц.
5. Открытые вопросы — то, чего нет в описании доработки (источник данных нового поля, условия доступности).
6. Разметки `bylo.txt` и `stalo.txt` — файлами рядом или блоками `text`.
