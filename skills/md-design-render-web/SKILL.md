# Невидимый прогон «Накидки» в веб-клиенте

Форма строится в веб-клиенте 1С внутри Firefox без окна. Нет окна 1С, кликов по экрану, общего буфера обмена и борьбы за фокус: пользователь продолжает работать, прогоны можно запускать в фоне. Снимки не зависят от разрешения и масштаба экрана пользователя: браузер рисует на виртуальном холсте 1600×1100.

## Вызов

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<каталог навыка>\scripts\render.ps1" `
  -Markup "<файл разметки .txt, UTF-8>" -OutDir "<каталог снимков>" -Prefix "<имя>" [-Pages "2,3"] [-Port 8099] [-EpfSource fork|release]
```

Результат — JSON `{ pages, files, notOpened, error, errorFile }`, снимки `<Prefix>-NN.png`: код 0 — успех, 1 — ошибка, текст в `error`. Ход подготовки скрипт пишет в stderr строками `[md-design-web] …`.

**Несколько разметок за один запуск** (состояния одного экрана): `-Markup "01-pusto.txt;02-zapolneno.txt;03-oshibka.txt"` — список одной строкой через `;`, потому что `powershell -File` не передаёт массивы. Результат — массив объектов того же вида с полем `markup`, снимки каждой разметки — `<имя её файла>-NN.png`, `-Prefix` не используется. Ошибка на одной разметке останавливает прогон: у неё свой `error`, у следующих — «не выполнено: прогон остановлен на ошибке в …»; код выхода 1. Три состояния диалога снимаются примерно за 30 секунд против 15 на каждое отдельным вызовом.

**Открыть готовую обработку** вместо разметки: `-OpenEpf <файл.epf>` — исполнитель открывает любую внешнюю обработку и снимает её форму по страницам (используется навыком md-design-to-epf для снимка собранной формы). Снимки — `<Prefix>-NN.png`.

**Только подготовить окружение**: `-PrepareOnly` — скачивает и собирает всё нужное и печатает JSON с путями (`web`, `runner`, `browsers`, `bin`, `epf`, `buildIb`, `mdDesignSrc`); прогона нет. Для навыков, которые пользуются этим окружением.

**Выбор страниц**: `-Pages "2,3"` — номера страниц верхнего уровня (с 1). Номер в имени файла исходный: снята только вторая страница — файл `-02.png`. Для формы без страниц параметр не действует.

## Подготовка окружения (один раз, повторно не выполняется)

Всё размещается в `%LOCALAPPDATA%\md-design-sandbox\web`, права администратора не нужны.

1. **Apache 2.4** — zip сборки Apache Lounge, сверка SHA256 с закреплённым значением (параметры `-ApacheZipUrl`, `-ApacheSha256`; при выходе новой сборки старая может исчезнуть с сайта — обновить оба).
2. **База-песочница** `md-design-sandbox\ib` (общая с экранным исполнителем) и строка `DisableUnsafeActionProtection=.*md-design-sandbox.*` в пользовательском `conf.cfg`.
3. **Публикация** — свои `httpd.conf` и `default.vrd`; сервер слушает только `127.0.0.1:<Port>`, модуль `wsap24.dll` берётся из установленной платформы.
4. **Playwright** (`playwright-core` через npm) и его сборка **Firefox**. Не Chrome и не Edge: в корпоративной среде их удалённое управление часто запрещено политикой `RemoteDebuggingAllowed=0` (так и на машине автора — и для Chromium тоже).
5. **MDDesign.epf — временно сборка из форка.** «Накидка» 0.16.4 в веб-клиенте не работает: нет `ЗаписатьJSON`/`ПрочитатьJSON` на клиенте, нет распаковки ZIP на клиенте, события редактора не доходят до 1С. Исправление — PR [crimsongoldteam/md_design#217](https://github.com/crimsongoldteam/md_design/pull/217) (issue #216). До его принятия скрипт клонирует `Romandredan/md_design`, ветку `fix/web-client-json`, и собирает EPF конфигуратором в отдельной базе `web\build-ib`; сборка кэшируется по коммиту. После выхода версии с исправлением — `-EpfSource release` по умолчанию.

## Прогон

1. Apache стартует обычным процессом; скрипт ждёт ответа публикации.
2. Сценарий `render.mjs`: открывает веб-клиент, «Файл → Открыть» (запасной путь — Ctrl+O), подставляет EPF в диалог «Выбрать с диска», передаёт разметку функцией редактора `window.setText`, нажимает «Сформировать».
3. Форма прототипа находится по DOM: префикс элементов `formN` — по закладке первой страницы (`.tabsItemTitle[data-content]`) или по заголовку формы (`formN_ЗаголовокФормы`). Закладки нажимаются по их положению, снимок кадрируется от заголовка формы.
4. Следующая разметка того же запуска открывает обработку заново в том же сеансе. Прототип строится внутри формы «Накидки», и при повторном формировании в том же окне часть элементов прежней формы остаётся теми же узлами страницы; новый экземпляр обработки даёт новый префикс `formN`, а элементы прежних форм помечаются до формирования — снимается только новая форма. Кроме того, в сборке форка до коммита `8e4e65f` поле редактора после «Сформировать» пустело.
5. Если веб-скрипт должен собрать обработку из другого источника (локальная копия форка для проверки исправления), `-ForkRepo <путь или адрес> -ForkBranch <ветка>`: адрес источника обновляется на каждом прогоне, сборка кэшируется по коммиту.
6. Окно «К сожалению, возникла непредвиденная ошибка» — снимок страницы, отчёт об ошибке (`<Prefix>-error-report.zip`, внутри `report.json` с текстом ошибки и стеком) и остановка с ошибкой. Ошибки клиента веб-клиента в журнал регистрации сервера не пишутся — текст только в этом отчёте.
7. Редактор не появился — снимок всей страницы `<Prefix>-debug.png` в `errorFile` и перечень фреймов в stderr.
8. Apache и его дочерние процессы останавливаются по PID; вместе с ними завершается сеанс 1С, поэтому следующий прогон начинается чисто. Если прогон прервать иначе, сеанс может остаться и следующий вход ответит «вход в приложение невозможен» — повторить прогон.

## Что увидит пользователь

При первом запуске Apache брандмауэр Windows может спросить, разрешить ли `httpd.exe` доступ к сетям, и попросить права администратора. Разрешать не нужно: сервер слушает только `127.0.0.1`, локальная работа не блокируется. Ответ «Отмена» Windows запоминает для этого файла. Предупредить пользователя об этом окне при первом запуске.

## Ограничения

- Проверен на Firefox из Playwright 1.48 и платформе 8.3.27 (версия для разработчиков). Сеанс веб-клиента на коммерческой платформе, вероятно, занимает клиентскую лицензию на время прогона.
- Проверен путь «открыть — ввести — Сформировать — переключить закладки», в том числе несколько разметок подряд. Другие функции «Накидки» в веб-клиенте (выгрузка в XML, файлы, чат ИИ) не проверялись.
- Снимаются страницы верхнего уровня; очень длинная форма снимается целиком, без прокрутки внутренних областей.
